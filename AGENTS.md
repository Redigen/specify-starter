# AGENTS.md - Specify Project Guidelines

## 🧠 Project Overview
Specify is a declarative UI specification and compiler. The entire UI, state, data fetching, and core business logic are defined declaratively in YAML (`specs/`). The compiler (`vite-plugin-specify-svelte-spa`) transforms these specs into a Svelte application.
TypeScript (`logic/`, `stores/`) is used ONLY as a fallback for complex, non-standard logic that cannot be expressed via YAML's built-in declarative methods.

## 🛑 GOLDEN RULES (CRITICAL)
1. **YAML-First / Declarative-First**: NEVER write TypeScript if the task can be solved using YAML's built-in actions (`post-data`, `get-data`, `set-state`, `navigate-to`, `set-notification`).
2. **NEVER edit files in `apps/specify-svelte-spa/src/generated/`**. They are auto-generated by the compiler.
3. **Tokens Only**: Never hardcode colors, sizes, or typography. Always use design tokens via `t.color`, `t.spacing`, `t.typography`, etc.
4. **Component Invocation**: Custom components are invoked in `layers` using the `c.` prefix (e.g., `c.MyButton`).
5. **Data & Mutations**: Use `get-data` for fetching (Appwrite databases, files, etc.) and `post-data` for mutations (create-row, login, upload-file).
6. **State**: Use local `state` (via `set-state`) for component/screen state. Use global `stores` (TS) ONLY if state must be shared across unrelated screens and cannot be passed via props.

## 📂 Directory Structure
- `specs/`: The single source of truth.
  - `app.yaml`: Global config, themes, integrations.
  - `tokens.yaml`: Design system tokens.
  - `screens/`: Screen definitions (`path`, `data`, `state`, `layers`).
  - `components/`: Reusable component definitions (`props`, `layers`).
- `apps/.../src/logic/`: Fallback only. Pure TS functions for complex logic not covered by the schema.
- `apps/.../src/stores/`: Fallback only. Global reactive state for complex cross-app scenarios.
